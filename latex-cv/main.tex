% changed for parsing reasons, all of them measured against the ATS
% findings on the generated documents:
%
%   1. PHONE. Was "+353: 0874261508". The colon after the country code is
%      not a format libphonenumber accepts -- Workday and Greenhouse
%      validate phone fields with it, and it failed to parse in every
%      region tested. Stripping the colon is not enough either: the bare
%      "0874261508" an extractor pulls out is ambiguous, and a parser
%      defaulting to Germany reads it as +49 874261508, a different
%      number a recruiter would actually dial.
%
%      "+353 087 426 1508" was the string that parsed valid in IE, DE, US
%      and with no region at all, normalising to +353874261508 in each.
%      The trunk 0 is what removes the ambiguity, so keep it.
%
%   2. FONT AWESOME ICONS ARE GONE. \faEnvelope, \faPhone and \faLinkedin
%      draw glyphs from a symbol font with no sensible Unicode mapping.
%      They extract as replacement characters welded to the value next to
%      them, which is how a contact line turns into an unparseable blob.
%      Plain text labels cost one line and cannot be misread.
%
%   3. CORE COMPETENCIES IS NO LONGER A 3-COLUMN multicols BLOCK. Columns
%      are the single most reliable way to break a resume parser: one
%      reading by vertical position interleaves the three columns into
%      nonsense. A single delimited line says the same thing and cannot
%      be read out of order. This is the same change the extension made
%      to its own competencies grid.
%
%   4. ONE EXPERIENCE SECTION, NOT TWO. "Software Engineering Experience"
%      as a second heading is invisible to parsers that bind to the first
%      experience block only, so anything under it is dropped.
%
% \pdfgentounicode=1 with \input{glyphtounicode} is kept and is the part
% of this template that actually makes it extract cleanly. Leave it in.
%
